# `std:kind`

What a value actually is.

```ts
import { kindOf, isPlainObject } from "std:kind";

kindOf(new Map());        // "map"
kindOf(new Point());      // "instance"
isPlainObject(new Map()); // false
```

`typeof` answers `"object"` for an object, an array, a Map, a Set, a Date and
a class instance alike. That is a problem rather than an inconvenience, because
nothing else in the language can separate them either: every `Object` method
that would tell you — `keys`, `entries`, `getPrototypeOf`, `hasOwn` —
**refuses** a Map, and a refusal is an uncatchable runtime error. So a function
that walks a value structurally had no safe way to ask what it was walking.

## Specification

| Export | Signature | Answers |
| --- | --- | --- |
| `kindOf` | `(value)` | one of the names below |

```
"null" "undefined" "boolean" "number" "bigint" "string" "symbol"
"function" "class" "array" "object" "instance"
"map" "set" "weakmap" "weakset" "date" "regex" "promise" "generator"
```

`"object"` is a **plain** object and `"instance"` is one with a class, because
that is the distinction a structural walk needs.

| Predicate | True for |
| --- | --- |
| `isPlainObject` | an object with no class — the only thing `Object.keys` can walk |
| `isArray` | an array |
| `isMap` / `isSet` | a Map / a Set, not a weak one |
| `isWeak` | a WeakMap or a WeakSet |
| `isDate` / `isRegex` / `isPromise` / `isGenerator` / `isInstance` | each of those |
| `isFunction` | a function **or** a class, both of which are callable |
| `isPrimitive` | anything with no interior: number, string, boolean, bigint, symbol, null, undefined |
| `isWalkable` | a plain object or an array — something a structural walk can take apart |
| `isCollection` | a Map or a Set, which have a `size` and an iterator |

## Implementation

**`Object.kindOf` is the built-in underneath**, added because the question
could not be answered in the language at all. It never fails, for any value.

**The fallback exists so the library stays checkable.** Every expected file in
`tests/cases/stdlib/` is generated by running the same program under Node, and
Node has no `Object.kindOf` — but it does have the prototype tag that CScript
lacks, and the two answer the same question. So `kindOf` asks whichever is
available. Without that, `std:assert`, `std:clone` and `std:json` would all
have lost Node as their oracle.

**Why `"instance"` is separate from `"object"`.** An instance's private fields
are invisible to any walk, so a structural copy or comparison of one would be a
different object wearing the same name. Every module that walks values treats
the two differently, and needs to be able to.

## Who depends on this

[`std:assert`](../assert) compares Maps and Sets structurally through it,
[`std:clone`](../clone) copies them, and [`std:json`](../json) writes them.
Before it existed, each of those took the process down on a Map rather than
mis-handling it.
