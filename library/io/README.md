# `std:io`

Files, and the two streams a program writes to.

```ts
import { readLines, writeText, out } from "std:io";

const lines = readLines("data.txt").unwrapOr([]);
out.line("read " + String(lines.length) + " lines");
writeText("out.txt", lines.join("\n") + "\n");
```

Over the `fs` and `console` built-ins, with one thing changed: every operation
that can fail answers a [`Result`](../result/README.md) rather than an
`{ ok }` object, so a failure composes instead of being unpacked at every call
site.

## Specification

### Reading

| Export | Signature | Answers |
| --- | --- | --- |
| `readText` | `(path)` | `Result` of the whole file as a string |
| `readLines` | `(path)` | `Result` of the lines, **without** the empty one a trailing newline leaves |

### Writing

| Export | Signature | Answers |
| --- | --- | --- |
| `writeText` | `(path, text)` | `Result` of the byte count; **replaces** the file |
| `appendText` | `(path, text)` | `Result` of the byte count |
| `writeLines` | `(path, lines)` | `Result`; each line gets a newline, the last included |
| `appendLine` | `(path, line)` | `Result`; the line plus a newline |

### Asking

| Export | Signature | Answers |
| --- | --- | --- |
| `exists` | `(path)` | a plain boolean |
| `isFile` / `isDirectory` | `(path)` | a plain boolean — false when the path is not there at all |
| `stat` | `(path)` | `Result` of `{ ok, size, isFile, isDirectory, modifiedMs }` |
| `size` | `(path)` | `Result` of the byte count |

### Arranging

| Export | Signature | Answers |
| --- | --- | --- |
| `list` | `(path)` | `Result` of the entries, **sorted**, without `.` and `..` |
| `makeDirectory` | `(path)` | `Result`; fails when it already exists |
| `ensureDirectory` | `(path)` | `Result`; already there is **success** |
| `remove` | `(path)` | `Result`; a file, or an **empty** directory |

### Streams

| Export | Is |
| --- | --- |
| `out` | a `Stream` to stdout |
| `err` | a `Stream` to stderr |
| `Stream` | the class, in case another one is wanted |
| `StringWriter` | the same three methods, collecting text instead of printing |

| Member | Signature | Behaviour |
| --- | --- | --- |
| `write` | `(text)` | writes with **no** newline; answers itself, so calls chain |
| `line` | `(text = "")` | writes and ends the line |
| `lines` | `(items)` | each item on its own line, `String()`-converted |

`StringWriter` adds `text()` for what it collected, `length` for how many bytes
that is, and `clear()`.

## Implementation

**Why `Result` here and `{ ok }` underneath.** `fs` is the layer that cannot
depend on a library module, so it answers a plain object; this is the layer
that can. Neither throws, because a runtime error in CScript is not catchable
and reading a file that might not be there is the most ordinary thing a script
does.

**An error carries the path.** `"No such file or directory"` on its own is the
least useful message a program can print, so every failure reads
`cannot read data.txt: No such file or directory`.

**`readLines` drops the trailing empty line.** A file ending in a newline has
as many lines as it has newlines — which is what `wc -l` says and what a caller
means. `writeLines` is its inverse, terminating the last line as well, because
a text file whose final line is unterminated is the thing every other tool
complains about.

**`list` sorts and `fs.list` does not.** A filesystem's order is not
meaningful, so a program that prints it unsorted produces output that differs
between machines for no reason a reader can see. The built-in leaves it alone
so that a program which *needs* the raw order can still have it.

**`ensureDirectory` treats "already there" as success.** The caller asked for a
directory to exist, and it does.

**`write` needs a built-in that `console.log` cannot provide.** `console.log`
ends the line and formats its argument; building output a character at a time
needs neither. That is what `console.write` is for, and why a partial line is
visible here rather than buffered until it is finished.

**Synchronous, because `fs` is.** CScript's event loop drives promises and
timers, not I/O, so an asynchronous file API would be a synchronous read
wearing a promise.

**Absent on purpose:** networking, spawning a process, and watching for
changes. None exists in the runtime, and a module that pretended otherwise
would be worse than one that says so.

## Node cannot check this module

Every other case in `tests/cases/stdlib/` has its expected output generated by
Node. This one cannot: `fs` is a CScript built-in with no Node counterpart, and
Node's filesystem module is a different API reached a different way. The
expected file was produced by CScript and checked against this document.
